Four-project layered solution (`Services.slnx`) following Clean Architecture / DDD conventions:
- `Services.Domain` is the innermost layer: POCO entities (`Project`, `TaskItem`, `User`), enums (`TaskCurrentStatus`, `TaskPriority`), and value objects (`Email`, `ProjectName`, `TaskTitle`, `TaskDescription`, `UserFullName`). No framework dependencies.
- `Services.Application` defines contracts only: repository interfaces under `Interfaces/Repositories/` (`IProjectRepository`, `ITaskRepository`) and service interfaces under `Interfaces/Services/` (`IAuthService`, `IProjectService`, `ITaskService`); DTOs live in `DTOs/{Auth,Projects,Tasks}/PagedResponse.cs`; application services (`ProjectService`, `TaskService`) are registered via `DependencyInjection.AddApplication`.
- `Services.Infrastructure` implements those contracts: Entity Framework Core `AppDbContext` with Npgsql against PostgreSQL, Identity configuration (`ApplicationUser`, `IdentityRole<Guid>`), JWT token generation (`JwtTokenGenerator`, `AuthService`), repository implementations, and EF migrations under `Persistence/Migrations/`. Registration happens through `DependencyInjection.AddInfrastructure(IConfiguration)` which validates connection string and JWT settings at startup.
- `Services.Api` is the thin HTTP entry point: controllers (`AuthController`, `ProjectsController`, `TasksController`) depend only on application interfaces; `Program.cs` wires middleware (`UseAuthentication`/`UseAuthorization`), maps OpenAPI + Scalar (`MapScalarApiReference`), and registers infrastructure then application layers. OpenAPI security scheme is customized via `BearerSecuritySchemeTransformer`.

Dependency direction is strictly inward: Api → Application ← Infrastructure, Domain has no outward references.
